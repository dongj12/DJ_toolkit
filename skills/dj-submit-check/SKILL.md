# 제출 전 점검

## 순서

1. 기계적 점검 스크립트를 실행한다 (이 SKILL.md 옆 `scripts/precheck.sh`):
   ```bash
   bash <이 스킬 폴더>/scripts/precheck.sh .
   ```
2. README를 다시 열어 요구사항을 하나씩 대조한다. 각 항목에 근거(파일·함수·테스트·확인 방법)를 붙인다.
3. README가 지정한 필수 파일명·경로·형식이 정확히 맞는지 확인한다 (대소문자, 확장자 포함).
4. 테스트와 스모크 확인을 마지막으로 한 번 더 돌린다 (`$dj-verify`).
5. PLAN.md(계획 문서)에 결정 기록, 검증 결과, 남은 한계가 채워져 있는지 확인하고 빠진 부분을 채운다.
6. 실행 중인 불필요한 서버·브라우저를 정리한다 (`/ps`, `/stop` 또는 `kill`). 단, 평가에 서버 실행이 필요하면 README 안내를 따른다.
7. 최종 커밋한다 (`$dj-checkpoint`, 메시지 예: `[DOCS] 최종 정리: 문서와 검증 결과 보완`).

## 보고 형식

```
## 요구사항 대조
- [x] R1 ... — 근거: app.py:add_item, test_add 통과
- [ ] R3 ... — 미구현 (이유: 시간 부족, PLAN.md 한계에 기록함)

## 필수 파일
- [x] README 지정 파일 ...

## 점검 스크립트
<WARN 항목과 조치>

## 남은 할 일 (우선순위)
1. ...
```

## 원칙
- 미완성은 숨기지 않는다. 안 된 것은 안 됐다고 PLAN.md 한계에 적는 편이 낫다.
- 이 단계에서 큰 기능을 새로 시작하지 않는다. 고치는 것은 작은 결함과 문서뿐이다.
- 끝나면 사용자에게 "웹 IDE에서 저장 상태 확인 → 제출하고 문제풀기"를 안내하고, 서술형 대비가 필요하면 `$dj-explain`을 권한다.
