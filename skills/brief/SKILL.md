# 내 작업 브리핑

목표: 사용자가 5분 안에 읽고, 질문을 받았을 때 자기 말로 답할 수 있게 만든다.

## 순서

1. 근거를 모은다 (출력은 짧게):
   - `git log --oneline --reverse | head -40`
   - `git diff --stat $(git rev-list --max-parents=0 HEAD | head -1) HEAD | tail -20`
   - PLAN.md 전체, README의 요구사항 부분
   - 진입점과 핵심 파일 2~3개 (전체 코드를 다 읽지 않는다)
2. 아래 형식으로 **터미널에만** 출력한다. 작업 폴더에 파일을 만들지 않는다 (제출물에 섞이지 않게).

## 출력 형식

```
# 한 줄 요약
<무엇을, 누구를 위해, 어떻게>

# 동작 흐름 (사용자 행동 → 결과)
1. 사용자가 ... → <파일/함수> → ...
2. ...

# 구조
- <파일>: <역할 한 줄>   (핵심 3~6개만)

# 핵심 결정 (선택 → 이유 → 대안)
1. ... → ... → ...

# 검증한 것
- <무엇을 어떻게 확인했고 결과는>

# 한계와 개선 방향
- <한계> → <시간이 있었다면>

# AI 활용
- Codex에게 맡긴 것 / 내가 직접 판단·수정한 것 / 거절한 제안과 이유

# 예상 질문 6개와 답변 뼈대 (각 2~3문장)
Q1. 왜 <결정>을 했나요?
A. ...
...
```

## 원칙
- PLAN.md와 커밋에 근거가 있는 내용만 쓴다. 기억나지 않는 것을 지어내지 않는다.
- 전문용어는 쉬운 말로 한 번 풀어준다.
- 실제 구현과 PLAN.md가 다르면 그 차이를 짚어준다 (서술형에서 전제가 틀린 질문이 나올 수 있다).
