# 과제 킥오프

목표: 10분 안에 "무엇을 만들어야 하고, 무엇으로 검증하며, 무엇을 먼저 할지"를 확정한다.

## 순서

1. 작업 폴더 구조를 본다: `ls -la`, `find . -maxdepth 2 -not -path '*/node_modules*' -not -path '*/.git/*' | head -100`
2. README와 과제 안내 문서를 끝까지 읽는다. 제공된 데이터·코드·테스트가 있으면 무엇인지 파악한다.
3. git 상태를 확인한다: `git status`. 저장소가 아니면 `git init` 후 첫 커밋("[INIT] 초기 상태: 제공 파일 그대로")을 만든다.
4. 아래 형식으로 사용자에게 보고한다.

## 보고 형식

```
## 한 줄 요약
<무엇을 만드는 과제인지>

## 필수 요구사항 (README 근거)
- [ ] R1. ... (README의 해당 문장 짧게 인용)
- [ ] R2. ...

## 제출물
- 필수 파일명/경로/형식: ...
- 실행·평가 방법: ...

## 애매한 점 → 실무자 에이전트에게 물어볼 질문
1. ...

## 제안 구성
- 언어/프레임워크: ... (이유 한 줄)
- 포트/실행 명령: ...

## 시간 계획 (총 180분 기준)
- 0~15분: 분석, 뼈대
- 15~120분: R1 → R2 → ... (우선순위 순)
- 120~145분: 검증, 예외 처리
- 145~155분: 문서 정리, 최종 점검 ($submit)
- 155~170분: 내 작업 설명 연습 ($brief → $brief 연습)
- 170분: 제출 시작 (종료 10분 전)
```

5. 사용자가 확인하면 PLAN.md를 만든다 (README가 다른 파일명을 지정했으면 그 이름을 쓴다). 뼈대:

```markdown
# PLAN

## 목표
<한 줄 요약>

## 요구사항
- [ ] R1 ...

## 결정 기록
### D0. 사용한 공개 도구
- 선택: DJ_toolkit@<`git -C ~/DJ_toolkit rev-parse --short HEAD` 결과> (https://github.com/dongj12/DJ_toolkit)
- 범위: 작업 규칙·검증 스크립트·문서 틀만 사용. 과제 로직은 이번 작업에서 새로 작성

(결정이 생길 때마다 $log 형식으로 추가)

## 실무자 확인 내용
| 질문 | 답변 | 반영 위치 |
|---|---|---|

## AI 협업 기록
(AI가 막히거나 틀렸다가 해결한 일을 $log 형식으로 추가)

## 검증 결과
(기능별 테스트·확인 결과)

## 남은 한계
```

## 원칙
- 요구사항은 README에 근거가 있는 것만 적는다. 추측은 "질문"으로 분리한다.
- 구성은 과제가 지정한 것을 우선하고, 지정이 없으면 가장 단순하고 익숙한 것을 고른다.
